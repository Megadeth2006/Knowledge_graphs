## Обновление среза

Из каталога проекта в Git Bash:

```bash
.venv/Scripts/python.exe import_ecoton.py --output new_sample.csv
```

Для воспроизведения из сохранённого HTML вместо сетевого запроса использовать `--html rental.html --date 2026-11-26`, подставив дату фактического чтения. Проверить адреса, условия и спорные записи, затем заменить `data/island_listings.csv` проверенным CSV, выполнить `build_graph.py` и перезапустить `search_app.py`. Без `--output` загрузчик записывает результат непосредственно в островной CSV. Он заменяет срез целиком после разбора и отвергает пустой результат или страницу с другим типом аренды. Исчезновение с первой страницы означает выход из текущего среза. Графы собираются заново, маршруты пересчитываются при старте сервера. Результаты поиска и восьми запросов воспроизводятся из переданных файлов даже при изменении сайта.

Авторазбор распознаёт ограниченный набор однозначных самостоятельных фраз о разрешении или запрете животных. Условные, противоречивые и нераспознанные формулировки требуют ручной проверки. В ноябрьском срезе явно распознан один запрет. Для точек новых домов требуется отдельное сопоставление с OSM. При изменении адреса старое соответствие по ID объявления не переносится.

Проверены открытая страница каталога, ссылки карточек, [robots.txt](https://ecoton.spb.ru/robots.txt) и уведомление о правах внизу каталога. При использовании текста издатель требует указать источник. Здесь сохраняются выбранные фактические поля и ссылки. Массовый обход карточек и воспроизведение описаний, фотографий или контактов для работы не требуются. У Циана автоматический сбор требует специального разрешения, а проверенные страницы каталога открывали CAPTCHA. Источником ноябрьского среза выбран «Экотон».

## Идентичность объектов

Каждая карточка имеет свой узел объявления и свой источник с URL и `dct:identifier`. В текущих двух срезах подтверждённых межплощадочных совпадений нет. Кандидаты R05 и R06 имеют парные пометки в `quality_note`, общий дом и отдельные квартиры. При документированном совпадении можно вручную задать один `verified_home_id` и основание `identity_evidence` в импортируемых строках. Объявления, цены и источники сохранятся отдельно, обе связи `offers` будут вести к одной квартире. Сборщик проверяет совместимость здания, этажа, площади и числа комнат.

## Октябрьские наблюдения Яндекс Недвижимости

Собрано шесть карточек Яндекс Недвижимости. Дата чтения: 22 октября 2026 года. Метод: ручное извлечение небольшого набора фактических полей из доступного текстового представления страниц. Это **сведения из объявлений**, а не факты, подтверждённые осмотром. Цена, наличие и условия могут измениться. Авторы проекта не связывались с владельцами.

R03 при первом обращении имел в поисковом представлении старое значение 30000, при повторном чтении самой карточки — 25000. В набор записано последнее прочитанное значение. Это показывает необходимость даты наблюдения. Воспроизводимость обеспечивается сохранённым CSV, а не обещанием, что сайт всегда вернёт те же значения.

R01: структурированное поле говорит об отсутствии мебели, описание перечисляет предметы мебели. Это поле не переносим в нормализованные свойства, конфликт отмечаем в quality_note. R05 и R06: сведения о лифте в карточке дома и тексте расходятся. R05 также содержит разные сведения о виде из окон. Не выбираем удобную версию без проверки. Один дом и одинаковая площадь не доказывают идентичность квартиры: номер квартиры отсутствует, автор упоминает несколько объектов. Поэтому `owl:sameAs` не используется, а предварительные сущности жилья остаются отдельными.

Для дома R04 отдельно получена опорная точка из OSM. У остальных домов октябрьского среза геометрия для пространственного поиска пока отсутствует. Минуты до метро из заголовка карточки не переносились: способ передвижения не всегда однозначен. Четыре месяца не превращаем в долгосрочный договор от 11 месяцев.

## 2. Словарь CSV

| Поля | Смысл и правило |
|---|---|
| id, source_id | Внутренний ID и ID объявления площадки |
| source_url, observed_on | URL карточки и дата чтения |
| rent_rub_month | Только заявленная арендная плата за месяц |
| area_m2 | Общая площадь квартиры |
| rooms | Число комнат, 0 означает студию |
| floor, floors_total | Этаж квартиры и этажность здания |
| deposit_rub | Залог в рублях, пусто = сумма неизвестна |
| commission_rub | Разовая комиссия в рублях, уже пересчитана из процентов |
| pets_allowed | true / false / пусто. Пусто не равно false |
| term | long_term либо fixed_short_term по описанию |
| min_months | Явно указанный минимум месяцев, иначе пусто |
| quality_note | Конфликт, кандидат в дубли, ограничение применимости |
| is_synthetic | false для реального среза |

`term=long_term` отражает формулировку объявления. Оно не доказывает конкретный юридический срок. R03 сохранён для проверки качества, но исключается из целевого отбора. Нулевой залог записываем только при явном указании. Все реальные КУ неизвестны в денежном выражении: их нельзя заменять нулём. R06 указывает оплату счётчиков, остальные — квитанции. Эти варианты не переводятся в выдуманные суммы.

## 3. Учебные данные

12 объявлений с ID D01–D12 и 6 инфраструктурных объектов M1–M2, S1–S2, P1–P2. Все цены, координаты, адреса и условия вымышлены. Географические координаты выбраны в диапазоне Санкт-Петербурга, но не обозначают квартиры по реальным адресам. DemoCity и DemoDistrict также учебные.

В учебном наборе условия о животных принимают три состояния: разрешено, запрещено, неизвестно. Поля `lat` и `lon` задают опорные точки зданий и инфраструктуры. В RDF они записываются в WKT с долготой перед широтой. Вопросы 2 и 7 вычисляют геодезическое расстояние между точками при запросе.

## 4. Пространственный пилот OpenStreetMap

Геопривязка R04 получена через Nominatim по адресу «улица Красного Курсанта, 51». Совпадение проверено по тегам здания OSM. Точка относится к дому. Этажность остаётся значением из карточки аренды. Географический источник указан отдельно. [Дом в OpenStreetMap](https://www.openstreetmap.org/way/39065438)

Снимок OSM от 13.11.2026 покрывает Петроградский остров и соседние участки для маршрутов через мосты. Граница отбора домов задана отдельно в `data/petrograd_island.geojson`. Это полигон отношения OSM 1312631. Сборка проверяет, что опорная точка дома R04 находится внутри него. [Петроградский остров в OSM](https://www.openstreetmap.org/relation/1312631)

Границы выгрузки в порядке запад, юг, восток, север: 30.246, 59.940, 30.3585, 59.982. Прямоугольник разделён на 15 участков для API карты. Координаты участков и дата сохранены в `data/osm_pilot.json.gz`. При повторении выгрузки каждый участок скачивается через `GET /api/0.6/map?bbox=...`, затем все XML передаются в `python osm_extract.py tile*.osm data/osm_pilot.json.gz --date YYYY-MM-DD --source URL`. При совпадении типа и ID сохраняется одна запись, с наибольшей версией. [API карты OSM](https://wiki.openstreetmap.org/wiki/API_v0.6#Retrieving_map_data_by_bounding_box:_GET_/api/0.6/map)

Нормализованный снимок содержит 294 объекта, 56 067 узлов и 19 656 отобранных линий пешеходной сети. Для точечных объектов используются координаты узла, для отобранных линий и площадей с полным набором вершин — центр ограничивающего прямоугольника.

Маршрут считается от точки дома с привязкой к узлу сети в пределах 45 м. Поиск идёт по разрешённым для пешего пилота участкам OSM до входа станции. Выходы и пути с известным запретом исключаются. Время оценивается по длине маршрута при скорости 1,4 м/с. Неполнота карты, время ожидания и часы работы могут влиять на фактическую длительность. Если подходящая привязка или путь отсутствуют, результат остаётся неизвестным. Пилот не покрывает весь город. По проверенным результатам геокодирования, например, Пулковское шоссе находится южнее прежней границы 59.88, а Русановская улица восточнее прежней границы 30.50.

## 5. Почему прежний набор не используется

Прежняя презентация ссылается на анализ объявлений **продажи** квартир. Цена продажи не является месячной арендной платой. Преобразование через произвольный коэффициент исказило бы предметную область. Ссылку на Kaggle нельзя считать готовыми данными об аренде.

Для этапа «Данные» сейчас есть реальный пилот с происхождением и пригодная для проверки модели структура. Для масштабного эксперимента и эмбеддингов этого недостаточно: разумная проектная цель — несколько сотен проверенных объявлений и связанная инфраструктура. Это план команды, не официальный минимум курса.

## 6. Расходы и права использования

Плата за первый месяц + залог + комиссия — известная часть суммы при въезде, а не гарантированный окончательный платёж. Неизвестные КУ и дополнительные услуги остаются вне суммы. Залог учитывается как требование к деньгам при въезде, но не как ежемесячный безвозвратный расход.

Пакет содержит небольшую фактографическую выборку и ссылки, без фотографий, телефонов, имён агентов и копий описаний. Открытая веб-страница не означает открытую лицензию на массовую выгрузку. При дальнейшем расширении предпочтительны разрешённые выгрузки, собственные записи либо набор с явно указанной лицензией. При публикации Git можно оставить синтетический набор и схему, а способ распространения реального среза согласовать отдельно.
